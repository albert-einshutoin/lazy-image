# 2.0.0: security and deprecated API removal

These changes continue from published 1.5.0. Registry availability and publication
dates are established by npm and GitHub Release records, not this document.
Source/candidate checks are not proof that arbitrary hostile images are safe.
The scope is one CMS job: turn an externally supplied static local image into
verified local public artifacts using `compileImage()`.

## Why a major version

Node >=22 support, compiler policies and metadata defaults stay unchanged.
1.5.1 was considered for the initial security-only scope. The removal of
`@jsquash/webp` changes the documented manual asset-copy source, requiring a
consumer deployment-script change. Under [SemVer policy](../SEMVER_POLICY.md),
the eight synchronized npm packages therefore use 2.0.0. No old vulnerable
runtime dependency is kept to preserve the previous directory layout.

2.0.0 also completes the two removals planned in #680.
This is a breaking JS/TypeScript API change; the initial #911 candidate kept
those APIs, and its SHA/hash-bound evidence remains a historical record.

## Native API migration (#680)

| Removed | Existing replacement |
| --- | --- |
| `engine.preset(name)` followed by `toBuffer`/`toFile` | `encode({ preset: name })`, `toBufferWithPreset(name)`, or `toFileWithPreset(path, name)` |
| TypeScript `EncodeOptions` | `EncodeOptionsInput` |

The unused `PresetResult` type is removed with `preset()`. The replacement
output APIs produce their result in one call and do not mutate the caller's
queued pipeline operations. For example:

```js
const engine = ImageEngine.fromPath('photo.jpg');
const { data } = await engine.encode({ preset: 'thumbnail' });
await engine.toFileWithPreset('avatar.webp', 'avatar');
// Later output still uses the caller's original pipeline, without a preset resize.
const original = await engine.toBuffer('jpeg', 85);
```

Use an explicit `resize()` when a persistent pipeline change is intended.
`encode()`/`encodeToFile()` retain their input and result contracts;
`toBufferWithMetricsPreset()` and other non-destructive output APIs remain.
`compileImage()` and metrics schema 1.1.0 are unchanged. See the
[TypeScript migration example](../TYPESCRIPT.md#200-migration).

## Loader and upload admission changes (#917)

Native package metadata must match the main version before the addon is loaded,
regardless of `NAPI_RS_ENFORCE_VERSION_CHECK`. Missing/malformed/mismatched
metadata or initialization failure is terminal. Only the six distributed native
platforms are supported; the generated unsupported/WASI fallback paths are removed.
Development builds and explicit absolute `.node` overrides require the adjacent
`.node.json` version/SHA-256 sidecar written after `npm run build` succeeds. Keep
the binary and sidecar together; do not stamp unknown or historical binaries.
The native runtime version is checked before API exports as well.

Wasm profiles now default to 32 MiB, 40 MP and a cooperative 5000 ms timeout.
JPEG/PNG/static WebP header dimensions are checked before decode, followed by
decoded/header consistency and output-size checks. Animated WebP and unverifiable
headers reject. This is a major-version admission change; callers supplying their
own limits should recheck them. Codec working memory, preemption and HTTP
deadlines remain deployment responsibilities. The Edge example requires an
application authorization decision and caps incremental body reads.

All eight packages include the project MIT license. Native packages include
compiled-dependency notices plus a normal/build dependency manifest binding
versions, Cargo.lock registry checksums and legal-source hashes. The path-only
libavif-sys dependency records its complete vendored source-tree hash instead.
Rust 1.88 standard-library/bundled-component notices accompany the native packages
in `RUST_STD_NOTICES.html`. `npm run licenses:check`
reproduces this conservative six-target union; build-only tools need not be linked.

## Measurement interpretation

Historical baseline warnings (JPEG bytes/time, WebP time, AVIF time and complex
time) remain recorded with the original 5%/15% thresholds. Incomplete historical
host/fixture/binary provenance prevents attributing those absolute differences to
a release regression. Matched process-pair medians and exploratory intervals
apply only to their recorded source/runtime/fixtures; the maximum complex ratio
3.096385 remains, and scheduler/core/JIT/queue causes are unknown. There is no tail SLA.

Quality and byte-budget matches are independent axes (37/39 each in the recorded
finite grid), not 37 simultaneous wins. Ordinary valid-input unmet axes remain:
transparent-AVIF input to JPEG/AVIF misses the sharp byte anchors; alpha-1/alpha-2
AVIF misses the quality floors. These differ from the deliberately impossible
10-byte Wasm best-effort budget (`budgetMet=false`) and expected strict `E502`.
No general speed, compression or perceptual-quality dominance is asserted.

## Security changes and provenance

- Wasm decoder, baseline encoder and SIMD encoder use libwebp 1.6.0, replacing
  embedded 1.1.0 for CVE-2023-4863. Shared initialization checks explicitly
  injected codecs too: version below 1.3.2 or unavailable fails initialization.
  [Source, pinned build and licenses](../../packages/lazy-image-wasm/vendor/webp/README.md)
  accompany the candidate. Rebuild with `npm run build:webp-wasm` (Docker).
- Native libavif 1.0.4 retains its ABI and rav1e 0.7.1 with the two upstream
  CVE-2025-48174/48175 fixes backported. See
  [source baseline, changes and removal condition](../../vendor/libavif-sys/SECURITY-PATCHES.md).
  The path-only Cargo dependency intentionally prevents packaging from replacing
  the fixes with the registry crate. Direct Cargo publication remains blocked.
- sharp 0.35.5 addresses CVE-2026-96889 in development comparisons/verification.
  sharp is not a dependency of the published runtime.
- The N-API Tokio lockfile dependency moves from 1.49.0 to 1.51.6, a patched
  version for AsyncFd I/O-safety advisory RUSTSEC-2026-0386. The audit originally
  rejected the candidate; this update adds no exception. This is distinct from
  the informational `paste` maintenance warning below.
- `paste` / RUSTSEC-2024-0436 is an unmaintained proc-macro warning, not a known
  runtime CVE. The root/fuzz exception remains owned by lazy-image maintainers,
  with reassessment due 2027-01-20 and removal conditions in
  [the exception record](../../.github/security/cargo-audit-exceptions.json).
  Do not describe this as zero warnings.

## Wasm migration

Install the candidate tarball while unpublished. After publication, pin
`@alberteinshutoin/lazy-image-wasm@2.0.0`. Rebundle the Worker and replace the
old copy source `node_modules/@jsquash/webp` with
`node_modules/@alberteinshutoin/lazy-image-wasm/vendor/webp`:

```sh
find node_modules/@jsquash/{jpeg,png,resize} node_modules/@alberteinshutoin/lazy-image-wasm/vendor/webp -name '*.wasm' -exec cp {} dist/ \;
```

Deploy the unchanged filenames alongside the new Worker bundle. Replace all
three WebP files, invalidate stale cached bundles/assets, and update explicitly
injected `wasmModules` decoder/encoder bindings as well. Old modules are rejected
before receiving image bytes. The [Wasm README](../../packages/lazy-image-wasm/README.md)
contains the complete browser and Edge setup. Wasm upload preflight remains a
separate, narrower API; it does not provide native `compileImage` parity.

## CMS acceptance and limits

The existing compiler contract detects JPEG/PNG/WebP by content, accepts static
inputs up to 32 MiB and 40 million pixels within the dimension guard, strips
EXIF/GPS/XMP and other private metadata, and verifies retained safe ICC. AVIF
is an output format, not an accepted input format. Malformed, unsupported,
animated, over-limit or unverifiable input/output fails with its contract error.

Compiler budgets are strict: no fitting result means no publication. Standalone
best-effort target-byte APIs can return `budgetMet: false`; this remains an unmet
outcome. The ordinary default quality search can still return E123. The five
second public-upload check is cooperative at processing boundaries, not a hard
timeout capable of interrupting an executing codec or an SLA. RSS/time evidence
is scoped to its fixtures, runtime and platform, not a hard process memory cap.

Artifacts are written in private sibling staging, verified, then committed by
directory rename. Cancellation, codec failure and timeout clean the unpublished
set; an existing output directory is rejected. The output parent must be trusted,
without concurrent replacement, and staging must share its filesystem. Consumers
own authentication, network upload admission, job queues, process isolation when
needed, storage and delivery. No new sandbox/platform is introduced here.

## Evidence and publication boundary

The preparation PR retains targeted and full verification commands/results.
Final candidate evidence must bind the merged SHA, version, package inventories,
source/license hashes, eight tarball hashes, 12 installed native smoke results
and separate Node/Chrome Worker/workerd Wasm results. Failed/unmet outcomes and
retry reasons remain part of the evidence. Prior dirty 1.5.0 tarballs are not
this candidate and are not evidence of published 1.5.0 behavior.

No 32-bit libavif exploit or arbitrary hostile-input safety proof is claimed.
Package-manager audits do not inspect every embedded C/Wasm component. See
[the release guide](../RELEASE.md) for the canonical workflow. Public release
commands are reserved for the subsequent publication task; this preparation
does not create or push tags, publish npm/Cargo packages, or create a Release.
