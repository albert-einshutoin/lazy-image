# v1.5.0 release notes draft

**Unpublished candidate.** This prepares native compiler and CLI improvements; it is not a published npm verification report. Wasm versions are synchronized, but its runtime, codecs, and feature set are unchanged.

Before updating, check representative inputs and policies. The corrected normal-JPEG initialization applies the requested quality; identical quality settings can now produce different bytes, hashes, sizes, and processing cost. Exact byte-budget search handles non-monotonic sizes and can cost more on tight budgets. Default-policy `E123` timeouts remain unresolved.

For budgeted upload/build jobs, an explicit ceiling can avoid starting at quality 100:

```json
{
  "widths": [1600],
  "formats": ["jpeg"],
  "placeholder": false,
  "budgets": [{ "width": 1600, "format": "jpeg", "maxBytes": 93782, "maxQuality": 90 }]
}
```

Use that policy with `compileImage({ inputPath, outputDir, policy })` or save it as `policy.json` and run `lazy-image compile input.jpg --out-dir out --policy policy.json`. After publication, install the exact main version with `npm install --save-exact @alberteinshutoin/lazy-image@1.5.0`; before publication, use the verified candidate tarballs.

The compiler accepts integer `maxQuality` values 30–100, defaults to 100, and searches down to 30. It returns the highest byte-fitting quality within that range. Lower ceilings exclude higher-quality output even when it could fit. They do not guarantee latency, perceptual quality, or acceptance of every input. The public-upload five-second limit is inspected at processing boundaries; it cannot forcibly stop an in-progress codec and is not an SLA. Keep strict failures private: the compiler does not publish unsuitable artifacts. Do not reset resource limits, blindly retry timeouts, or deliver partial candidates as successful compiler output.

## Included changes and compatibility

- Compiler/CLI `policy.budgets[].maxQuality` is an additive public option, so this release is MINOR under the [SemVer policy](../SEMVER_POLICY.md). Omission and explicit 100 retain the previous canonical policy semantics; non-default ceilings have distinct fingerprints/cache keys.
- JPEG quality, non-monotonic byte-budget selection, and cumulative resource metrics are bug fixes toward the documented contract. The metrics shape/version is unchanged. Their observable output and cost changes above still require an update check.
- The manifest-to-static-HTML example demonstrates technical integration. It does not demonstrate real-user adoption or market fit.
- Native compiler evaluation records preserve quality and byte misses. No broad quality, compression, or speed superiority is claimed.
- Main, six native platform packages, and Wasm are synchronized to 1.5.0. Wasm does not gain the native compiler or its new policy option. No codec/backend/profile addition, dependency update, or held Dependabot change is included.

The [2026-10-12 maxQuality evaluation](compiler-budget-max-quality-20261012/EVALUATION.md) used a historical checkout on one M4 with three trials per condition: JPEG1600 / 93,782 B / maxQuality90 accepted 3/3 API and 3/3 CLI at q60 (API p50 about 3.35 s); AVIF320 / 12,850 B / maxQuality60 accepted 3/3 each at q60 (API p50 about 97 ms). Omitted ceilings retained API timeout and CLI E123 refusals. These are historical checkout observations, not measurements of published 1.5.0, cross-platform timing thresholds, p99, or universal acceptance guarantees.
