# oxipng 10.2.1 adoption hold: native PNG comparison

This is the fixed-input comparison behind the [PR #833 adoption hold](https://github.com/albert-einshutoin/lazy-image/pull/833#issuecomment-5863058293). The main baseline was `3ffc865739268ae7bd8afa4c0a6882c67a640f12` with oxipng 10.1.1. The candidate was `36cd5c45daa357e5015dc2bb075534e0abda5b44` with oxipng 10.2.1 in both lockfiles. The evidence-only commit that adds this directory does not change the measured code or dependency resolution.

`compare.cjs` is the exact one-off script used for the comparison. It checks the local N-API binding, uses sharp 0.35.4 to normalize input and output to 8-bit sRGB RGBA, and records output size, SHA-256, dimensions, pixel SHA-256, alpha counts, metadata, one cold call, and five sequential warm calls. The timed interval is `ImageEngine.from(input)` through the completed `toBuffer('png')` call, including decode and encode. The UI case also checks `toFile(..., 'png')`. The grayscale input is generated by the script from the repository's PNG chunk helper.

The JSON files contain the first and repeated old/new runs. The second pair (`baseline-repeat.json` and `candidate-repeat.json`) is used for the table in the PR comment. Only the machine-specific absolute `runtime.binding` path was replaced with `lazy-image.darwin-arm64.node` in these committed copies; the binding SHA-256 and all measurements are unchanged. Each JSON records the input hashes and exact case results.

## Reproduction

Run each revision in its own clean checkout on the same macOS arm64 host. For each checkout:

```sh
npm ci
RUSTUP_TOOLCHAIN=1.88.0 SDKROOT=/Applications/Xcode.app/Contents/Developer/Platforms/MacOSX.platform/Developer/SDKs/MacOSX26.5.sdk npm run build
COMPARE_ROOT="$PWD" COMPARE_LABEL=baseline COMPARE_SHA="$(git rev-parse HEAD)" node /path/to/compare.cjs
```

Use `COMPARE_LABEL=candidate` for the updated checkout. The script writes `lazy-image-833-<label>.json` to the system temporary directory. It expects the local `lazy-image.darwin-arm64.node` and the repository fixtures, and refuses to continue if a different binding is loaded. Node 24.2.0, Rust 1.88.0, sharp 0.35.4, and the macOS 26.5 SDK were used for both measured builds. The metadata fixture's EXIF Orientation was disabled in both versions to isolate PNG optimization; other cases used default options without a PNG quality argument.

All seven cases preserve normalized pixels and alpha, including nonzero RGB under full transparency. Default metadata stripping and explicit ICC preservation also pass. The UI case increases from about 19–20 ms to 33–34 ms, and the 64×16 grayscale case from about 1.5 ms to 12.6–12.9 ms in warm API calls, with no meaningful output-size gain. These are input- and host-specific results, not a universal benchmark or a measurement of `encodeMs` or `peakRss`. Re-evaluate those two cases, size, PNG contract, and resource metrics before adoption.
